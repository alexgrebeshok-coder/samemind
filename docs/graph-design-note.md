## 0. Что уже есть в коде (не выдумывать)

В продукте граф **уже есть**. С 1.1 словарь **закрыт на чтении** (expand,
validate, `query rel`); парсер по-прежнему принимает любой ключ. Формулировка наряда «только `[[wiki]]` без типа и направления» — про восприятие, не про репозиторий. По коду на момент принятия:

| Слой | Где | Что делает |
|---|---|---|
| Хранение | markdown + YAML frontmatter, `tools/lib/okf.mjs` `parse()` / `load()` | Узел = файл. Источник правды — файлы бандла, не БД. |
| Markdown-ссылки | `okf.mjs:214` | Из тела (вне code/inline-code) вытаскиваются только `[text](path.md)`. Это и есть «wikilink» продукта. |
| `[[wiki]]` | комментарий `okf.mjs:306–307` | Формат зеркал Claude Code. `validate`/`links` их **не** разбирают. В живом бандле ~30 штук, большинство не резолвится в id концепта (`[[skill-lifecycle]]`, `[[x]]`, `[[ссылок]]`). В `demo/` — 0. |

| `supersedes` | top-level frontmatter, `docs/memory-hygiene.md`, `okf.mjs:219–223` | Гигиена, **не** ребро графа. Намеренно вне `relations:`. |
| Конфликт 0.7.0 | `CHANGELOG` 0.7.0, `hygiene.mjs` `findContradictions` / `applyConflictTiebreak` | Живые пары (один `type`, Jaccard ≥ 0.34, никто никого не supersede’ит) **не выкидываются**. Порядок: authority ↓ → recency ↓ → score. Проигравший помечается `⚔ conflicts with <id>`. Stale/deprecated по умолчанию не в выдаче (`--include-superseded` — аудит). |

| Карта связей | `okf-query.mjs` `buildLinksModel`, HTTP `/api/graph`, контракт `kind: "links"` | Уже отдаёт `edges[]` с `kind: "link" \| "relation"` и `rel: <открытый ключ>`. `supersedes` рисуется как `rel: "supersedes"`. |

## 1. Решение по хранению (чтобы код за день не ломал схему)

1. **Источник правды остаётся файлом.** `relations:` в frontmatter, как сейчас. Новой БД рёбер, Neo4j, таблицы sqlite под граф — нет.
2. **Словарь закрывается на чтении**, не на парсере. `normalizeRelations` по-прежнему принимает любой ключ (иначе сломаются demo, бандл, шаблоны, чужие бандлы). `validate` начинает **предупреждать** на ключ вне словаря и вне таблицы алиасов. Жёсткий fail — не в 1.0.
3. **`cites` не пишется в frontmatter.** Это вывод из тела: markdown `[text](….md)`, уже в `doc.links`.
4. **`supersedes` не становится `edge_kind`.** Остаётся гигиеной. Если в файле стоит `relations.supersedes` (шаблоны так учат) — читающий слой 1.0 обязан считать это алиасом top-level `supersedes` и **не** ходить по нему как по соседу expand. Иначе старый план всплывёт как `+hop`, хотя 0.7.0 его как раз прячет.
5. **Обратные рёбра не храним.** Inbound считается при обходе, как уже делает `expandHits` и `query rel --inbound`.
6. **sqlite-vec не расширяем рёбрами.** Индекс — про поиск, граф — про файлы. Дублировать рёбра в `index.db` = вторая схема и рассинхрон.

Переименовывать файлы бандла пакетом **не надо**. Алиасы ниже читаются как канон.

## 2. Закрытый список `edge_kind`

Семь хранимых + один выводной. Восемь — потолок, который ещё размечают.

Правило отбора: ребро обязано закрывать вопрос при **чтении**. Тип, который нужен только доске или только писателю, в словарь не входит.

### 2.1 `about` — «о чём / к какому делу»

- **Пояснение:** узел высказывается про другой узел: решение про проект, план покрывает инициативу, задача принадлежит проекту.
- **Направленность:** да. `from` — высказывание/работа, `to` — предмет.
- **Откуда:** пишет человек (курация). Движок не угадывает.
- **Вопрос при чтении:** «что мы решили / запланировали / должны по X?»
- **Алиасы уже существующих ключей:** `about`, `covers`, `project`.

### 2.2 `member_of` — «куда входит / где работает»

- **Пояснение:** человек в организации, движок в идентичности агента, концепт в родительском узле.
- **Направленность:** да. `from` — член, `to` — целое.
- **Откуда:** человек.
- **Вопрос при чтении:** «где работает Iris / частью чего является этот engine / в какой идентичности это правило?»
- **Алиасы:** `works_at`, `part_of`.

`works_at` оставляем писать как привыкли в demo; на expand он равен `member_of`.

### 2.3 `depends_on` — «без чего это не стоит»

- **Пояснение:** структурная зависимость: проект или концепт не читается без другого концепта.
- **Направленность:** да. `from` нуждается в `to`.
- **Откуда:** человек.
- **Вопрос при чтении:** «на чём стоит этот проект / эта стратегия?»
- **Алиасы:** `depends_on` (канон совпадает с уже живущим ключом).

Не путать с `uses`: зависимость — «не существует без», использование — «берёт как инструмент».

### 2.4 `uses` — «чем пользуется»

- **Пояснение:** человек/проект/идентичность применяет систему, агента, движок, продукт.
- **Направленность:** да. `from` пользуется `to`.
- **Откуда:** человек.
- **Вопрос при чтении:** «каким агентом пользуется Саша? какой retrieval стоит под Lumen?»
- **Алиасы:** `uses`.

В identity-слое это уже основной ключ (`Identity.uses` → EngineRule, `User.uses` → Identity). Не схлопывать в `depends_on`: вопросы разные.

### 2.5 `agreed_with` — «с кем согласовано»

- **Пояснение:** план или решение согласованы с конкретным человеком.
- **Направленность:** да. `from` — Plan/Decision, `to` — Entity/User.
- **Откуда:** человек, в момент фиксации («не записал — не было»).
- **Вопрос при чтении:** «с кем это согласовали? кого звать на встречу по этому плану?»
- **Алиасы:** `agreed_with`.

Не заменяется `about`: «про Lumen» ≠ «согласовано с Iris».

### 2.6 `informs` — «на каком основании / во что выросло»

- **Пояснение:** более ранний узел питает более поздний: анализ → идея, ресёч → идея, идея → план, сессия породила решение, анализ породил ресёч.
- **Направленность:** да. `from` — основание/источник, `to` — следствие.
- **Откуда:** человек на курации (агент пишет в inbox, канон — после гейта). Движок сам канон не рисует.
- **Вопрос при чтении:** «почему мы это придумали? из чего вырос план? что решили на той сессии?»
- **Алиасы:** `informs`, `spawned_by` (это **обратная** запись того же ребра: `Research spawned_by Analysis` ≡ `Analysis informs Research`), `led_to`, `decided`.

`spawned_by` при чтении разворачивается: направление канона — от источника к следствию. Inbound `informs` на Analysis и так отвечает «какой ресёч из этого вырос».

### 2.7 `related` — «рядом, точного типа нет»

- **Пояснение:** слабая симметричная связь «смотри также». Единственный симметричный тип.
- **Направленность:** нет. A related B ≡ B related A. Хранить достаточно одну сторону; обход смотрит обе.
- **Откуда:** человек, только когда не подходит ни один тип выше.
- **Вопрос при чтении:** «что ещё лежит рядом с этим правилом / этим концептом?»
- **Алиасы:** `related`.

Expand ходит сюда **последним** и только если бюджет ещё жив. Иначе мусорный ящик съест пятёрку соседей.

### 2.8 `cites` — «кто ссылается» (не хранится)

- **Пояснение:** кто-то в теле файла сослался markdown-ссылкой на этот концепт.
- **Направленность:** да. `from` цитирует `to`.
- **Откуда:** следует из данных (`doc.links` → `resolveLinkId`). Человек не размечает.
- **Вопрос при чтении:** «кто ссылается на этот узел?» — ровно то, что 0.9.0 уже тянет как reverse wikilink.
- **Алиасы:** нет ключа в `relations:`.

Исходящие `cites` хита **не** раскрываем — это уже закон 0.9.0 и тест `recall-expand.test.mjs` («the hit's own OUTBOUND wikilink is NOT pulled»). Страница, которая машет руками на десяток соседей, иначе топит ответ.

`[[имя]]` в 1.0 **не** становятся `cites`. Парсер их не знает; в живом бандле они часто не id. См. §5.

## 3. Что из живых ключей сознательно не вошло

| Ключ сегодня | Почему не `edge_kind` | Куда девается |
|---|---|---|
| `next` (Session → Task) | Вопрос «что дальше?» закрывает **доска**, не recall. Inbound с задачи тянул бы старые сессии в `+hop`. | Остаётся конвенцией work-discipline. Expand **не ходит**. `validate` не ругается — это известный внесловарный ключ доски, не ошибка разметки. |
| `supersedes` / `superseded_by` | Уже гигиена 0.7.0. Второй канал «кто кого заменил» разъедется с ranking. | Top-level поля. `relations.supersedes` читать как гигиену, не как соседа. |
| `conflicts_with` | Конфликт уже **вычисляется** (`findContradictions`). Писать его руками = два источника правды. | Метка `⚔` на выдаче, отчёт `reconcile`/`consolidate`. |
| произвольный новый ключ | Никто не разметит двадцатый тип. | `validate` ⚠️; expand игнорирует. |

`next` — единственный «белый» внесловарный ключ: доска его читает, граф чтения — нет.

## 4. Expand — как обход меняет выдачу

Цель expand не «показать граф», а **добрать контекст, без которого ответ врёт**: человек без организации, проект без решения, идея без основания.

### 4.1 Когда расширять

| Поверхность | 1.0 |
|---|---|
| `samemind recall` / `okf-recall.mjs` | Как сейчас: только `--expand` / `--expand-hops 1`. Без флага вывод **байт-в-байт** как без графа (инвариант 0.9.0, тесты уже держат). |
| MCP `memory_search` | `expand: true`, соседи в отдельном блоке `expanded`, не в `results`. Контракт уже такой (`docs/json-contract.md`). |
| Протокол агента (`docs/memory-protocol.md`) | Агент **включает** expand, если среди top-k есть якорь вопроса: `Entity`, `User`, `Project`, `Plan`, `Decision`, `Idea`, `Identity`. Для голого факта («какой authority у поля») — не включает. |
| `samemind proactive` | **Не** расширять. Пакет и так под char cap; граф туда — это шум в преамбуле. |

Авто-expand без флага в CLI не включаем: сломаем инвариант «без флага = как вчера» и контракт 1.0.

### 4.2 Глубина и бюджет

- Глубина **1**. `--expand-hops > 1` уже честно режется (`okf-recall.mjs:122–123`). 2-hop на личном бандле (~150 узлов) превращает любой хит про Сашу в половину канона.
- Бюджет по умолчанию **5 на все сиды вместе**, не на хит. Уже так.
- Соседи **не** получают score и **не** пересортировывают top-k. `score: 0` + подпись `(+1 hop from <id>)` — оставить.
- Сид повторно как `+hop` не добавлять (уже так).

### 4.3 Какие рёбра ходить и в каком порядке

Сейчас `expandHits` сваливает все `relations` + inbound links в один `Set` и режет бюджет порядком обхода объекта. В 1.0 — очередь по типу:

1. `about`, `member_of`, `agreed_with`, `depends_on`, `informs`, `uses` — оба направления (как `rel` CLI).
2. `cites` — **только inbound** (кто сослался на хит).
3. `related` — оба направления, если бюджет ещё есть.

Не ходить: `next`, неизвестные ключи, `relations.supersedes`.

Подпись `+hop` в 1.0 должна нести **канонический kind** (`about` / `member_of` / … / `cites`), не сырой ключ файла. Алиас нормализуется до печати. Иначе агент снова видит зоопарк.

### 4.4 Конфликт — не изобретать, стыковать с 0.7.0

Политика уже написана. Expand её исполняет, не дублирует.

1. **Соседа нет, если он не live** — `isDeprecated` или `isStaleForRecall` (superseded / `superseded_by` / `invalid_at` / `valid_from`). Это уже в `expandHits`. Сохранить. `--as-of` прокидывать, как сейчас.
2. **Живой конфликт не прячем.** 0.7.0 не дропает пару, только ставит победителя выше и вешает `⚔`. Если сосед в противоречии с сидом (тот же детектор `findContradictions`) — показать соседа и дописать ту же метку. Не подменять гигиену новым `conflicts_with`.
3. **Tiebreak не смешивает блоки.** `applyConflictTiebreak` работает внутри ranked `results`. Блок `expanded` — не рейтинг. Двух противоречащих соседей в `+hop` не сортируем друг относительно друга и не тратим бюджет на замену: оба, с меткой, пока влезают.
4. **`--include-superseded`.** Если вызвали аудит — expand тянет stale с той же
   пометкой, что и recall. Без флага — нет. **Сделано в 1.1** (`includeSuperseded`
   parity в `expandHits`; MCP `include_superseded`).

`reconcile` по-прежнему предлагает, не пишет. Авто-ребро «этот факт победил тот» из Jaccard — запрещено.

### 4.5 Как не утопить ответ

Жёсткие крышки, не эвристики «на глаз»:

1. Budget 5 на весь expand.
2. Очередь kind (§4.3), не FIFO по YAML.
3. Нет исходящих `cites`.
4. Нет `next`.
5. Нет 2-hop.
6. Соседи не в ranking и не в proactive.
7. Полное чтение тела — по-прежнему 3–5 узлов протокола. Expand говорит «сосед есть»; `memory_get` агент делает сам и только если сосед отвечает на вопрос.
8. Secret/mirror не в пуле, пока не передали те же флаги, что у recall (уже централизовано в `load()`).

Если после крышек сосед не влез — это не баг. Агент пишет в «чего память не покрывает», как велит протокол.

## 5. Что НЕ делаем в 1.0

Раздел обязателен: он экономит недели.

1. **Neo4j / Memgraph / отдельный graph DB.** Исследование 25.07 (`agentic-kg-graph-experience`) уже отвергло это как дефолт. У нас файлы + git. GraphDB = вторая правда и деплой.
2. **Таблица рёбер в sqlite-vec.** `index.db` — векторы. Рёбра в нём устареют в ту же секунду, как поправили frontmatter без `index`.
3. **N-hop / BFS / «пока бюджет» глубже 1.** Флаг уже врёт, если просят 2. Честная подпись + один hop.
4. **LLM-извлечение рёбер сразу в канон.** Capture → inbox, курация пишет `relations`. Иначе граф станет галлюцинацией со структурой.
5. **Парсить `[[wiki]]` как рёбра.** Парсер их не знает; в бандле они часто не id. Ломать зеркала Claude ради 30 кривых скобок — нет. Если позже — только `[[id]]`, резолвящийся в существующий концепт, и только как `cites`.
6. **Хранить `conflicts_with`.** Детектор 0.7.0 + human-gate `reconcile`. Писать конфликт руками = он разъедется с Jaccard/authority.
7. **Вес, дата, provenance на ребре.** Узел уже несёт `timestamp` / `authority` / `source`. Ребро 1.0 — kind + два id.
8. **Массовый rename ключей в бандле.** Алиасы на чтении. Переименовать `works_at` → `member_of` во всех файлах — отдельная кнопка Саши, не условие 1.0.
9. **Закрыть парсер (fail на неизвестный ключ).** Сломает чужие бандлы и шаблонный `next`. Сначала ⚠️.
10. **Авто-expand в CLI и в proactive.** Сломает инвариант «без флага = как вчера» и токенный потолок преамбулы.
11. **Визуализация сверх `/api/graph` и `query links`.** Карта уже есть. Рисовать kind-aware UI — после того, как expand начнёт печатать канонический kind.
12. **Обратные рёбра в файле.** Inbound считается. Дубли `A.member_of B` + `B.has_member A` разъедутся.
13. **Циклы по `relations` как ошибка validate.** Цикл ловим у `supersedes` (замена не может быть кольцом). У `related`/`depends_on` цикл — нормален.
14. **Temporal validity на ребре.** `valid_from` / `invalid_at` живут на узле. «Работал в Acme с 2024 по 2025» в 1.0 — текст в теле + смена `member_of` через новый узел/supersede, не поля на ребре.

## 6. Что сделано в 1.1 (код принят до этого наряда)

1. `tools/lib/relation-kinds.mjs` — канон → алиасы, очередь обхода, `cites` derived.
