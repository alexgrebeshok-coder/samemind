# Голосовой спутник — как подключить и не наступить на грабли

> Практический документ для человека, который ставит локальный ASR-сервис
> рядом с samemind. Спека контура — `docs/spec/voice.md`. Ядро **не**
> содержит распознавания речи и **не будет**: оно говорит с любым
> OpenAI-совместимым endpoint через `voice.serviceUrl` — ровно как с
> эмбеддингами через `OKF_EMBED_URL`.

## Зачем так

Спутник — это **порт, а не зависимость**. Ядро остаётся zero-dependency и
кроссплатформенным: не тянет SpeechAnalyzer, whisper.cpp, Core ML и не
собирает нативный код. На macOS спутник — обёртка над системным
SpeechAnalyzer (или другим локальным ASR); на Linux — whisper.cpp-сервер
или любой иной OpenAI-совместимый `/v1`. Тот же приём, что с эмбеддингами:
конфиг указывает адрес, ядро ходит HTTP, «кто слушает микрофон» живёт снаружи.

Реализация пробы: `tools/lib/probe-voice.mjs` (`probeVoiceCompanion`).
Состояния доступности: `tools/lib/settings.mjs` (`assessAvailability`).
Дефолты и три согласия: `tools/lib/feature-config.mjs` (`VOICE_DEFAULTS`).

## Три честных состояния

`assessAvailability` (и экран «Настройки») различает **три** состояния.
`available: true` бывает только у `reachable`.

| Состояние | Когда | `available` | Смысл |
|---|---|---|---|
| **`unavailable`** | `voice.serviceUrl` не задан (`null` / пусто) | `false` | Нечего включать. Reason + fix: «установи спутника, затем задай serviceUrl». |
| **`configured`** | URL задан, но проба **не** передана | `false` | Адрес есть, достижимость **не доказана**. Note: «use check connection». |
| **`reachable`** | URL задан **и** `voiceProbe` от пробы успешен | `true` | Живой OpenAI-совместимый ответ на `GET /v1/models`. |

### Почему заданный адрес ≠ «работает»

Это тот же дефект, который продукт вычищал в **0.15** (конфиг/запись
считались «подключением», пока живой JSON-RPC и корпус не проверялись).
Запись `serviceUrl` в `.samemind/config.json` — только **намерение**.
Отрисовка настроек (`buildSettingsModel` → `GET /api/settings`) **чистая и
синхронная**: без сети, без spawn. Медленный или мёртвый спутник не должен
тормозить каждый poll дашборда.

Достижимость **никогда не вычисляется** на рендере: она **передаётся**
результатом `probeVoiceCompanion`, который крутит только
`GET /api/voice/probe` (кнопка «проверить связь»). Пока пробы не было,
состояние остаётся `configured` с `available: false` — экран **не**
рисует зелёный «работает» по одной только строке в конфиге.

### Что делает проба

- `GET <serviceUrl>/v1/models` (таймаут 2 с), **только GET**.
- Не POST аудио, не `/v1/audio/transcriptions`, не admin/auth, не warm-up модели.
- Успех: тело с массивом `data` → `{ url, engine: 'openai-compatible', model }`.
- Мёртвый, refused, slow, malformed JSON → `null` (ожидаемый «недоступен», не exception).

## Проверенные варианты спутника

Не рекомендация одного «правильного» — меню. Ядру нужен **OpenAI-совместимый
HTTP** (как минимум `GET /v1/models`; транскрипция — по контракту спутника,
когда контур начнёт слать аудио).

| Вариант | Платформа / заметка |
|---|---|
| **`ohr`** | CLI и OpenAI-совместимый HTTP-сервер; macOS 26+; собирается Command Line Tools **без** полного Xcode. |
| **`maclisten`** | ~500 КБ; вывод JSON-строками; есть режим непрерывного слушания. |
| **`speech-analyzer-cli`** | CLI вокруг системного SpeechAnalyzer. |
| **`dictamac`** | Ещё один macOS-вариант вокруг системного ASR. |
| **whisper.cpp-сервер** | Linux / кроссплатформенно: локальный HTTP с OpenAI-совместимым API. |

Любой другой локальный сервис с тем же контрактом `/v1` подходит — проба
проверяет договор, не бренд.

## Грабли (чужой опыт — ради этого документ)

Собрано из разборов чужих проектов (SpeechAnalyzer / CLI / бандлы), не
выдумано. Повторять не обязательно; знать — обязательно.

### 1. Подпись ad-hoc + entitlements

Бинарник, который дергает SpeechAnalyzer, **обязан** быть подписан ad-hoc
с нужными entitlements. Иначе падает с **`SIGTRAP`** при первом же
обращении к API. `swift run` шаг подписи **пропускает** — собирать надо так,
чтобы подпись реально выполнялась (скрипт/схема, которая после линковки
ставит codesign + entitlements). Симптом «собралось, при старте ASR — trap»
часто именно это.

### 2. App-бандл для разрешения на распознавание

macOS запрашивает permission на speech recognition через **app-бандл с
метаданными приватности** (`Info.plist` / usage description). Голый
CLI-бинарник такого разрешения **не получит**. Рабочие проекты складывают
`.app` рядом и линкуют/запускают исполняемый файл **из** бандла (или
оборачивают CLI как helper внутри бандла), а не ждут диалога у «голого»
`./bin`.

### 3. Первый запуск качает языковую модель

Системный SpeechAnalyzer (и часть обёрток) при первом языке может
**скачать языковую модель**. Нужна сеть **один раз**; дальше — локально.
Офлайн-машина без предварительного прогрева даст «тихий» отказ или долгий
первый запуск, который легко спутать с «спутник мёртв».

## Как подключить

1. Поставь спутника (любой из таблицы выше или свой `/v1`).
2. Задай **`voice.serviceUrl`** — базовый URL без хвоста `/v1/models`
   (например `http://127.0.0.1:8000`):
   - экран **«Настройки»** дашборда (`POST /api/config` пишет whitelist
     ключей в `<root>/.samemind/config.json`), или
   - правка `.samemind/config.json` вручную / global `~/.samemind/config.json`
     (project перекрывает global, как у эмбеддингов).
3. Нажми **«проверить связь»** — это `GET /api/voice/probe`, **по кнопке**,
   не при отрисовке. Успех → состояние `reachable` и model id из ответа.
4. Включи нужные флаги согласия (см. ниже) — все по умолчанию **выкл.**

После пробы экран может показать note вроде
`companion reachable (model-id)`. Без пробы даже с URL — `configured`,
не зелёный «доступен».

## Границы приватности

- **Сырой звук не покидает устройство.** ASR — у спутника локально; ядро
  samemind не встраивает микрофонный пайплайн.
- **Три согласия разделены намеренно** (`VOICE_DEFAULTS` в
  `tools/lib/feature-config.mjs`). Не схлопывать в один тумблер:

  | Ключ | По умолчанию | Решение |
  |---|---|---|
  | `enabled` | `false` | Доступ к голосовому контуру / микрофону как к capability |
  | `storeTranscripts` | `false` | Хранить расшифровки (и `transcriptRetentionDays`) |
  | `sendTextToLlm` | `false` | Отправлять **текст** (не сырьё) в LLM |

  Микрофон ≠ хранение расшифровок ≠ отправка текста в модель. Это три
  разных человеческих решения; продукт не включает их «пакетом».

- `serviceUrl: null`, `confidenceThreshold: 0.6`, `trigger: 'hotkey'`,
  `wakeWord: false` — тоже дефолты; первый запуск ничего не слушает.
