## samemind 1.0.0 — contract frozen

1.0 adds no features. It marks that the JSON contract stopped moving and that a
dogfood week ran clean on a live bundle — the two conditions the owner set for the tag,
nothing more.

### What freezes

- **The JSON shape is locked**, as written in `docs/json-contract.md`. After this release,
  changing the *form* of an existing field — its type, its nesting, the semantics of its
  value, or its name — is a **major** version bump. Adding a new optional field stays
  **minor**. Nothing on a documented surface changes shape inside a minor or patch release.
- **Errors stay bare.** `{ error }` / `{ error, errors }` is not wrapped into the
  `{ contract, kind, generatedAt, data }` envelope. Confirmed uniform across every failure
  path in `tools/lib/ui-server.mjs`; moving errors into the envelope later is itself a
  breaking change, not a silent patch.
- **The CLI and the HTTP `/api/*` routes** share the envelope described above and freeze
  together. **MCP tools are a second, separate contract** under the same discipline: their
  result shape is *not* the CLI envelope, and it must not silently become it — that swap,
  either direction, is a major of the surface being changed. What each returns today is
  what `docs/json-contract.md` documents — that file is the authority, not this note.

### Fixed before the freeze — the one thing 1.0 changes

`GET /api/board` and `GET /api/handoff` shipped the raw model: absolute host paths and the
full markdown body of every document. 0.17.0 announced this defect as fixed — and it was,
in the CLI, which runs the model through `projectBoardJson` / `projectHandoffJson`. The HTTP
twins skipped that step and stayed open. The re-check before signing 1.0 caught it.

Both surfaces now apply the same projection and return the same keys, byte for byte. This
had to land **before** the tag: freezing the leaked shape would have made closing it a major
version, so the leak would have outlived 1.x. A regression test now fails if either surface
drops the projection.

If you consume `/api/board` or `/api/handoff` and depended on `body` or `file` being present,
that is the one break in this release. Fetch a body per document via `GET /api/concept/<id>`.

### And one the release gate itself caught

`summarizeLedger` compared timestamp strings with `>=`. A `fail` and the `done`/`ok` that
closes it, written in the same millisecond, produced equal strings — so the topic stayed
open forever. Ordering inside one millisecond now comes from position in the stream.

This matters more than a stray assertion: `openFailures` is what `dogfood` counts, and
`dogfood` is the gate that decides whether a release is allowed at all. The bug could only
invent an open failure, never hide a real one, so previous clean-week verdicts stand.

It surfaced on Node 20 during the 1.0.0 release run, after passing twice on Node 22 where
the two writes never landed in the same millisecond. The gate held and the tag waited.

### Dogfood week

The instrument built in 0.17.0 (`samemind dogfood`) measured it directly: on the live
bundle, 9 days without an open failure, first event 2026-08-03, nothing open since. That
is the clean week the owner asked for before a tag was on the table.

### Not in 1.0

- **Graph memory — typed edges and multi-hop expand beyond the current 1-hop default.**
  The closed `edge_kind` vocabulary and the read-time rules for walking it are a design
  decision, not yet code; see `docs/graph-design-note.md`. It ships in **1.1**, not here,
  because the storage schema it depends on would need to move twice otherwise — once now,
  once when the vocabulary closes. 1.0 freezes what already runs; it does not freeze a
  half-built graph layer under it.

### Not a new release of features

No feature in 1.0 that was not already in 0.9.0–0.18.0. Apart from the HTTP payload fix
above, this tag changes nothing a user runs — it changes what they can rely on not changing
under them.

### Known, not fixed here

`board` and `handoff` accept `--root <dir>` silently and ignore it: the bundle comes from
`OKF_ROOT` instead, so `samemind board --root ./other-bundle` reports on the wrong bundle
without saying so. The flag is documented for `status`, `dogfood`, `serviced` and `ui`, never
for these two. It changes no payload shape, so it is not a freeze blocker and is not held
against the tag — it is a behaviour bug, fixable in a patch.
