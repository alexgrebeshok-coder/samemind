## samemind 1.0.1 — `--root` actually picks the bundle

A patch. Nothing about the JSON shape moved: the `{ contract, kind, generatedAt, data }` envelope
and every key under `data` for `board` and `handoff` — CLI and HTTP alike — are byte-identical to
1.0.0. That was checked against the 1.0.0 tree, not assumed, which is the only way a freeze means
anything.

### `--root` did nothing in `board` and `handoff`

Everywhere else in this CLI — `status`, `nudge`, `serviced`, `service`, `ui`, `dogfood` — `--root
<dir>` names the physical OKF-bundle root to work on. In `board` and `handoff` it named nothing.
`board` loaded concepts, `ledger/events.jsonl` and `fleet/registry.json` from `OKF_ROOT` no matter
what, and `--write` always wrote `DASHBOARD.md` there.

The failure mode is the bad kind: `samemind board --root ./other-bundle` exited 0 and printed a
board. It was just the wrong bundle's board, wearing the right bundle's name. Nothing in the
output said so.

Now the two flags answer the two different questions they read like:

- `--root <dir>` — **which** bundle to read.
- `--project <id>` — **what** to keep within it.

They are independent and compose. `samemind board --root ./b --project lumen` reads `./b` and
scopes its task columns to lumen. In `board`, one root serves the whole run — concepts, event
ledger, fleet registry, and the `--write` target — so a run rooted at B can no longer surface A's
open failures or A's overdue engines under B's heading. In `handoff`, documents come from the
selected root and `--project` stays a filter over them.

A `--root` that does not exist is now an error naming the path, not a silent fall back to
`OKF_ROOT`. So is one that exists but is not a directory: pointing `--root` at a file used to
produce an empty board or an empty brief, because the directory read failed quietly and left
zero documents behind — indistinguishable from a real bundle with nothing in it. A symlink to
a directory is still accepted, since bundles do get symlinked into place; a symlink to a file,
or a dangling one, is not.

### Three smaller lies in the same family

**A missing flag value passed silently.** `board --root` at the end of a line — or `--root --json`,
where the next flag would have been swallowed as the value — became "no value given", and the run
continued against `OKF_ROOT`. All value-taking flags (`--root`, `--project`, `--out`, and
`handoff --days`) now exit non-zero and say which flag is short a value.

**`samemind --version` printed the usage banner.** Same defect class as the `nudge --help` fix in
0.18.0: the flag was never routed, fell through to "unknown command", and printed help. A script
piping `samemind --version` got a page of prose instead of `1.0.1`. Both `--version` and `-v` now
print the version and exit 0.

**`handoff` could pick a different last session depending on walk order.** Sessions were compared
with `a.ts < b.ts ? 1 : -1`, which never returns 0 — not a valid comparator on ties. Ties are
ordinary here: two writes in the same millisecond, or a hand-written `date` with no time at all.
Once enough of them collided, V8's sort resolved the order inconsistently. The comparator now falls
back to `id`, unique per document, so the same bundle yields the same last session no matter what
order its files were read in.

### One thing that may break a script

An unrecognized `-`-prefixed argument to `board` or `handoff` is now an error. Before, it was
ignored — which is exactly how a mistyped or unsupported flag came to look accepted. Positional
arguments are still left alone. If you have a script passing a flag these two commands never
supported, it will now fail loudly rather than quietly doing something other than what it says.

### How this was checked

The full suite (`node --test tools/*.test.mjs`) ran green on **Node 20 LTS and Node 22**, the two
versions CI covers. On Node 20 the optional `node:sqlite` backend is absent, so the sqlite-index
tests skip themselves there, as they have since 0.18.0 — that is the runtime gate working, not a
failure. No exact test count is quoted here on purpose: it changes with every commit, so a number
in a release note is stale the moment it is written and tells a reader nothing they can act on.

The claim that the JSON shape did not move was checked rather than asserted: the 1.0.0 tree was
exported to a separate directory and the key skeleton of `board --json` and `handoff --json`,
with and without `--project`, was diffed against this release's — no difference. `--root` behavior
is covered against the tools directly and, separately, through `bin/samemind.mjs`, so the wrapper
dropping a flag on its way to the routed script would fail the suite too.
