## samemind 1.1.0 — graph read path: closed dictionary, kind-priority expand

Minor release. **Additive** MCP fields only; CLI/HTTP JSON envelope unchanged.
No graph database, no n-hop, no parser hard-fail on unknown relation keys.

### What changed

- **Closed read-side vocabulary** for typed `relations:` edges — expand, validate,
  and `query rel` walk canonical kinds (`about`, `member_of`, `depends_on`, `uses`,
  `agreed_with`, `informs`, `related`, `cites`). Files keep legacy aliases
  (`works_at`, `covers`, `spawned_by`, …); they normalize on read.
- **`validate` warns** on unknown relation keys (exit 0). `next` stays a board
  whitelist key — not unknown, not expandable.
- **`recall --expand` / MCP `expand: true`** — kind-priority queue; `+hop` / `expanded`
  rows show canonical `kind`. `next`, unknown keys, and `relations.supersedes` are
  not walked.
- **`--include-superseded` / `include_superseded`** — expand neighbors follow the
  same stale/superseded hygiene as primary hits.

### What did not change

- Recall **without** expand is byte-identical to 1.0.
- Frozen CLI/HTTP contract (`docs/json-contract.md` §1–6).
- Storage: markdown frontmatter only; no edge table in sqlite.

### Agent protocol

Pass `expand: true` when a top-k hit is an anchor type: `Entity`, `User`, `Project`,
`Plan`, `Decision`, `Idea`, `Identity`. Skip for plain fact lookups.
